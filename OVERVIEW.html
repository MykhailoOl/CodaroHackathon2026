Courtly

A Warsaw sports-facility booking app, plus an intent layer that turns a sentence like “tennis for two tomorrow evening, outdoor” into ranked, bookable slots with the reasoning attached.

  • Java 21
  • Spring Boot 4.1
  • Thymeleaf
  • Spring Security
  • H2 file DB
  • Next.js 14

What already works

The booking app / server-rendered

Register and sign in, browse venues and courts, pick a date + start hour + 1–4 hours, add extras and a coach, and get a PLN quote before submitting. Players create pending bookings; managers confirm them from a day queue. Live occupancy board, cancellation with a reason, dynamic evening/weekend pricing, coach offerings and ratings.

The intent layer / JSON API + Next.js

One sentence in, up to three ranked suggestions out — each with a price, a per-term score breakdown, and a plain-English reason. When nothing fits, it relaxes the request one rung at a time and tells you what it gave up. Book straight from a suggestion.

Both share one database, one security config, and one pricing service. The intent API reuses the same reservation rules — including the pessimistic lock that stops two people taking the last free slot.

How it fits together

BrowsersThymeleaf pages :8080 · Next.js app :3000
Webcontroller/ (MVC) · intent/web/ (REST, bearer token)
ServicesReservation · Pricing · Coach · Notification · Intent
Intent enginepure Java — no Spring, no JPA, no clock
DataSpring Data JPA → H2 file at ./data/

The intent engine is deliberately sealed off: IntentSchedulingService is the only class in intent/* that touches a repository. It loads a snapshot of resources and reservations, hands it to the ranker, and prices the winners. Everything downstream is a pure function of its inputs, so the same request always ranks the same way.

The pipeline

  • parse
  • snapshot
  • candidates
  • filter (hard)
  • score (soft)
  • explain
  • relax if < 2 survive

Sports, constraints (indoor, outdoor, floodlit, team), and scoring weights are declared in application.yml under intent: — never as literals in the engine. Adding a sport or reweighting the ranking is a YAML edit and a test run.

Run it

1 · Backend — from the repo root

./gradlew bootRun          # Windows: .\gradlew.bat bootRun
# → http://localhost:8080  (seeds venues, courts, extras, staff logins)

On startup it tries to open Firefox at /login and /h2-console. Turn that off with --app.browser.auto-open=false.

2 · Intent frontend — optional, in a second terminal

cd web && npm install && npm run dev
# → http://localhost:3000

It calls the API at localhost:8080 and falls back to bundled demo data if the backend isn’t up, so it demos either way. A badge on each screen tells you which you’re looking at.

3 · Tests

./gradlew test             # 24 test classes: overlap, capacity, pricing,
                           # parsing, ranking, relaxation, intent API

Poke at it

  1. Book something

    /facilities → a venue → a court. Pick a date, an hour, a duration, party size, extras. The total updates before you submit. Your booking lands as pending.

  2. Confirm it as staff

    Sign in as manager and open /manager/reservations. Confirm the booking; the coach extra on it confirms too. Try cancelling a confirmed one — it won’t let you.

  3. Watch the board fill

    /occupancy shows every court hour by hour. Click a free hour and it drops you into that booking form with the hour preselected.

  4. Talk to the scheduler

    At localhost:3000, sign in and type an intent. Try “squash for two tomorrow morning”, “football with friends this weekend, outdoor, 2 hours”, or something impossible like “outdoor swimming tonight” to watch the relaxation trail explain what it dropped.

  5. Or hit the API directly

    curl -X POST localhost:8080/api/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin123!"}'

curl -X POST localhost:8080/api/intent/suggest \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <token>' \
  -d '{"text":"tennis tomorrow evening, outdoor","partySize":2}'

  6. Look underneath

    /h2-console with sa / sportsbooking and the JDBC URL from application.yml. Business and security events also land in logs/courtly-audit.log.

Where the edges are

Payments are recorded, not taken. Cash / card / transfer is stored on the reservation. Nothing is charged and no coach is paid out.

The LLM parser is optional and off. CodaroIntentParser calls an OpenAI-compatible endpoint when intent.llm.base-url and api-key are set; unset, every request falls through to the rule-based parser, which handles the demo phrases on its own.

Coach hire is an extra on a place booking — not a standalone marketplace, and not available on group lessons.
